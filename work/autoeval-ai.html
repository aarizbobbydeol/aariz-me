AutoEval AI

A web app that runs the same prompts across several LLMs, scores the answers, and compares quality, speed and token use.

The problem

Comparing LLMs by hand is slow and inconsistent: you paste the same prompt into each model and judge the answers by eye.

AutoEval AI is for a developer choosing between Claude, GPT and Gemini. It runs one saved set of test prompts against several models, scores every answer automatically, and puts quality, speed and token use side by side.

How it works

  1. Build a test setCreate a named set of prompts, each with an optional expected answer. Six starter sets with 30 test cases cover maths, logic, code, facts, summaries and following instructions.
  2. Set up a runPick a test set, one or more models (four presets or any model the gateway supports), and a scoring method.
  3. Call each modelEvery prompt goes to every model at temperature 0 through one gateway, recording latency and input and output tokens. A failed call is kept with its error.
  4. Score each answerExact match, word overlap, or an LLM judge: Claude Haiku 4.5 returns a score from 0 to 1 with a short reason.
  5. CompareThe results page shows each model's average score, average latency and total tokens, with charts and every answer alongside the judge's reasoning.

What it measures

0–1quality score for every answer
mslatency of every model call
tokensinput and output, per call and per model
4preset models: Claude Sonnet 4.6, Claude Haiku 4.5, GPT-5.4, Gemini 3 Flash

Where it stands: the app runs end to end, but there's no published benchmark run yet, and the rubric scorer still reuses the judge. Next: a first public run across all four models, and tests.

Decisions I made

  • One gateway for every provider, so a single key covers Claude, GPT and Gemini, and a new model is just a name to type in.
  • Temperature 0 for both the model being tested and the judge, so repeated runs give comparable scores.
  • Plain JSON files instead of a database, so it runs locally with no setup. The trade-off: it won't keep data on serverless hosting.
  • If the judge's reply can't be read, the answer gets a neutral 0.5 instead of crashing the whole run.
