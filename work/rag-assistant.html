RAG Knowledge Assistant

Document question answering with citations to the exact page, which refuses when the fact you asked about isn't in the documents.

Role
Solo: design to deploy
Year
2026
Stack
Python, FastAPI, React, TypeScript, BM25 and vector search, Docker
Links
Live demo (wakes in about 30 s), Code

The problem

People who need answers from their own PDFs and internal documents can't trust a chatbot that answers fluently even when the documents never state the fact.

This assistant answers with numbered citations back to the exact passage and page, and refuses when the specific fact is missing, naming the term it looked for and the document it searched.

How it works

  1. Load and chunkReads PDF, Markdown, HTML, text, JSON and CSV, and splits it into overlapping chunks that keep their page numbers so a citation can point at a page.
  2. Index twiceEach chunk goes into a vector store and a BM25 keyword index, written together so recall never quietly drops.
  3. RetrieveFollow-up questions are rewritten to stand alone. Keyword and vector results are fused, diversified and reranked, and the top five passages are kept.
  4. Check before answeringIf a key term of the question, like “SEV-4”, isn't actually in the passages, it refuses and says which term was missing. No LLM call is needed for this.
  5. AnswerBy default it quotes passages with no API key at all, or it uses any OpenAI-compatible model when a key is set. Every sentence must carry a citation.
  6. VerifyCitations the model invented are removed and the rest renumbered, then each sentence is scored against the passage it cites.

Results

0.994recall@5 on 58 answerable questions
0.924nDCG@5 (MRR 0.915)
8 of 8unanswerable questions refused
1 of 58answerable questions refused by mistake
632tests passing on Python 3.11 and 3.12
+0.039nDCG gained from reranking

From the CI evaluation gate on a 66-question test set, which fails the build if these numbers get worse. See the run.

On a harder set of 60 held-out questions, the refusal check cut the share of unanswerable questions it answered anyway from 77% to 57%. That's better, not solved, and it's the number I'm working on.

Decisions I made

  • Retrieval written by hand instead of with LangChain, so fusion, diversity, reranking and the grounding check are each small, visible and tested on their own.
  • Works with no API key by default, so anyone can reproduce every number offline, and the public demo has nothing to leak or run up.
  • Swapped score thresholds for per-term checks after finding that pooled scores rated unanswerable questions as fully covered.
  • Pinned the CI gate at the measured numbers, so a change that makes refusals worse fails the build instead of just printing a lower score.
